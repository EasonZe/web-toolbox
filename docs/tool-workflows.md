## 接收规则

1. 来源必须已有有效结果，点击后才生成 File 并交接；处理中的批量任务不允许发送。正常下载入口保留。
2. 仅通过客户端路由进入固定白名单目标，URL 不携带文件名、字节或 Blob URL。
3. 目标显示来源、文件数量及“追加 / 替换”行为；必须再次点击接收，不自动覆盖输入或开始导出。
4. 接收调用目标原有输入处理函数，仍检查格式、数量、容量、PDF 页数等；图片补做与 FileDropZone 一致的文件头 / 像素预检，大文件先明确提示。
5. 成功后清空交接；失败返回 false 或抛错时暂时保留，用户可重试、忽略，或显式展开文件列表下载。

图片转 PDF、图片压缩按批次校验，不导入半批后保留整批导致重复添加。PDF 加页码 / 裁切和图片加文字会替换输入并清除旧输出，接收提示明确说明；不会覆盖磁盘上的原文件。

原有工具限制不放宽：例如页面管理可以输出 2000 页，而加页码 / 裁切的输入上限仍为 1000 页。超过目标能力时会按原处理逻辑报错，传入文件仍可在接收区保存或忽略。

## 具体实现与理由

- `app/lib/tool-handoff.ts`：固定五个目标及元数据约束，只保留一个待接收批次的文件引用。新批次替换旧批次；确认、忽略和超时按 ID 操作，旧操作不能清除新文件。不序列化、不上传，不使用 localStorage、sessionStorage 或 IndexedDB。
- `app/components/tool-handoff.tsx`：共享发送与接收界面，通过 `useSyncExternalStore` 订阅，服务端快照始终为空；文件备份链接只在用户展开时创建。接收期间检查页面是否卸载、批次是否更换以及输入回调 / 忙碌状态是否变化，避免已失效的预检再导入旧文件。检测偏保守，输入状态变化后需要重新确认。
- `app/components/images-to-pdf.tsx`、`pdf-page-tools.tsx`：提取现有上传回调为可确认成功 / 失败的函数，手动上传和交接共用，处理参数与输出不变。
- `app/components/image-compressor.tsx`、`image-converter.tsx`、`image-color-replace.tsx`、`video-capture.tsx`、`pdf-page-manager.tsx`：只在输出存在时添加适合的后续工具；传递的是结果 Blob，不是原始输入或缩略图。
- `app/components/image-text-editor.tsx`：输入函数反馈成功 / 失败，并修正已有的异步错误路径——旧图片加载失败不再覆盖新图片的状态。正常文字、对话框、预览与下载保持。
- `app/globals.css`、`app/styles/additional-utilities.css`：新区域复用原有按钮、禁用态、下载链接与主题变量，旧选择器的特异性保持；转换工具的后续操作放在原双按钮网格外，避免桌面只占半列。新文件列表按需展开、限定滚动高度并允许长名称换行，不改原页面布局。

## 文件生命周期与边界

待接收文件只存在于当前标签页的 JavaScript 内存，刷新、关闭、离开页面触发 pagehide 后不可恢复。未接收批次五分钟到期释放；浏览器后台冻结可能延迟定时器清理，快照与实际接收前仍检查期限。成功接收后文件由目标工具持有，按目标原生命周期释放，不是再过五分钟删除已经导入的输入。

这不是工作区保存、任务历史、跨标签页分享或后台队列。来源页面卸载时仍释放自己的预览 URL 和处理资源；交接持有 File，而非已撤销的 URL。中间文件如需长期保留，应使用下载。没有文件恢复或无限内存保证，也不把客户端格式校验当作病毒检测。
