# 首屏主题初始化

## 原因

原有 `app/layout.tsx` 只输出默认 HTML，`app/globals.css` 默认浅色。保存的深色与强调色要等客户端 `FloatingDock` 激活并执行 effect 后才写入根元素，因此首次绘制会短暂使用浅色；实际等待时间由脚本加载与设备运行情况决定，不是固定延时。

## 修改

- `app/lib/appearance.ts` 集中管理原有存储键、主题枚举、七种预设色及自定义颜色计算。保持无偏好时默认浅色，不更改既有色值。
- `app/layout.tsx` 通过 `beforeInteractive` 注入同一套规则的同步内联脚本，在正文前恢复根元素的主题、`color-scheme` 和强调色，无额外网络请求，不隐藏页面。
- `FloatingDock` 继承首屏已恢复的状态，后续仍可切换、保存与跟随系统变化；兼容存储被禁用和旧版媒体查询监听，并清理监听器。
- 根元素背景使用现有 `--page`；原有主题切换过渡、工具动画和页面布局不变。

初始化只接受主题枚举与六位 HEX，不把存储内容拼进 HTML。没有放宽 CSP；今后新增 CSP 时应通过框架 nonce 或脚本哈希授权。内联脚本不写入存储，持久化仍由设置组件负责。

## 产物回归

仅测源码不足：SSR 构建器会提前折叠裸 `typeof window`，导致序列化后的浏览器脚本丢失存储读取分支。共享函数使用 `globalThis` 进行运行时探测，测试直接取生产 HTML 内真实脚本执行，覆盖首页与工具页，断言其位于 head、同步且只有一份。

回归还覆盖保存的深色、跟随系统的两种结果、无偏好、存储与媒体查询异常、自定义颜色校验、首屏与设置颜色一致、挂载后不回退、系统变化和监听清理。

这些是生产 SSR、JavaScript 平台边界与组件逻辑测试，不等于真实浏览器的首帧录像或手机实机验收；未测量白屏持续时间或页面加载速度。

验证结果：生产构建、ESLint、TypeScript 与全量 894 项测试通过，0 失败、0 跳过；其中主题相关 24 项回归覆盖源码、设置组件与正式产物。项目一致性为 95 项依赖、124 个工具、125 条站点地图 URL，依赖与部署配置未变。
