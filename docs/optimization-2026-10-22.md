## 问题、影响与处理理由

| 优先级 | 具体文件 | 已确认问题与影响 | 修改及理由 |
| --- | --- | --- | --- |
| 高 | `package.json`、`package-lock.json` | Vite 8.1.5 被 npm 审计列为受影响版本，涉及开发服务器及 Windows 编辑器启动路径；不等于线上已遭利用。 | 只升级同分支安全补丁 8.1.6；测试约束修复版本下限，不通过忽略告警或大版本迁移解决。 |
| 高 | `app/components/tool-search-grid.tsx` | 渐入 effect 只依赖结果数量；连续搜索“时间戳”和“文件哈希”均返回一项，但 DOM 已换，新卡片可能没有观察器而保持隐藏。 | 依赖实际的、经 memo 稳定的结果数组。非收藏筛选下点星标仍返回同一个数组，不会重置动画。四种排列方式均补充回归。 |
| 中 | `app/lib/pdf-pages.ts`、`app/lib/pdf-selection.ts` | 实际导出写死 300 页，和集中策略及页面提示的 2000 页冲突。旧拆分逐页调用合并逻辑，每次重新加载全部来源。 | 统一使用 `toolLimits.pdf.outputPages`；校验来源、页码、旋转和总页数；每次任务只解析被引用的文档一次。顺序、旋转、文件名和原文件保持不变。 |
| 中 | `app/workers/local-files.worker.ts`、`vite.config.ts`、`app/components/pdf-page-manager.tsx` | 文本、ZIP、PDF 引擎静态绑定在同一 Worker，做 JSON 校验也要加载 PDF 引擎；页面只解析页码也导入 PDF 模块。生成的二进制结果通过结构化克隆额外复制。 | 按操作动态导入，Worker 使用 ES 模块产物；把纯页码解析独立成小模块，保留原模块兼容导出；生成的输出缓冲转移所有权，用户仍会使用的输入不转移。避免首任务无关下载和大结果额外复制。 |
| 中 | `app/components/currency-converter.tsx`、`app/api/exchange-rates/route.ts` | 换货币后旧数据仍可按新币种展示；异步返回后没有检查取消。服务端没有超时，且只检查 rate 的真值，可能接受负数或字符串。 | 只展示匹配当前货币对的数据；忽略已取消结果；交换时仅反转匹配的数据。上游请求采用 8 秒截止时间并跟随调用方取消，验证正数、有限的数值汇率。有效结果仍沿用原缓存策略。 |
| 中 | `app/components/plain-text-editor.tsx`、`app/lib/draft-autosave.ts` | CodeMirror 每次文字变化都同步写入整份草稿；长文连续输入时重复阻塞主线程和浏览器存储。 | 合并 400 ms 内的连续写入，只保留最新草稿；页面隐藏、pagehide、组件卸载时立即补存。关闭自动保存时取消待存任务，避免之后重新写回已删除草稿。编辑、撤销和字数显示不延迟。 |

安全依据：[Vite / launch-editor Windows 命令注入公告](https://github.com/advisories/GHSA-587h-7wmj-h5pm)、[Vite 开发服务器跨源脚本公告](https://github.com/advisories/GHSA-9jrq-w75r-8gcw)。此次 npm 审计共发现一个受影响依赖节点，补丁后全依赖审计为 0 项已知告警；这是当日快照，不是无漏洞保证。

## 可比数据

使用同一台电脑、Node.js v24.15.0；没有改变样本与指标。运行 `npm run build` 后执行 `npm run bench:local` 可复测。脚本为 `scripts/measure-local-performance.mjs`。

| 指标 | 修改前 | 修改后 | 说明 |
| --- | ---: | ---: | --- |
| 24 页 PDF 拆分源文档解析次数 | 24 | 1 | 相同的 6422 字节生成文档；包含各页保存，不含最终 ZIP 打包 |
| 同样本拆分耗时中位数 | 116.26 ms | 36.83 ms | 预热 1 次、计时 5 次，最终复测约减少 68.3%；小样本本机微基准，不代表所有真实 PDF |
| 冷文本任务脚本原始体积 | 554016 B | 25379 B | 入口、文本引擎及全部静态 JS 依赖的合计，减少约 95.4% |
| 上述脚本逐文件 gzip 合计 | 220543 B | 9283 B | gzip 压缩估算，减少约 95.8%，不是实际 CDN 流量测量 |
| 连续 100 次编辑的草稿写入次数 | 100 | 1 | 测试中每次间隔小于 400 ms，结束后统一保存；离开页面会额外补存尚未提交的最新草稿 |

修改后不同轮次中位数为 28.18–36.83 ms，表中使用最终构建后的最后一次复测，没有选择最快一次。没有测得网站 LCP、INP、真实弱网耗时或手机峰值内存，因此不将上述数据称为“全站加载速度提升百分比”。工作线程总大小仍包含用户实际选择的 PDF/ZIP 引擎，优化的是不需要它们时的加载路径。
